===== INTERPRETATION =====
The workload is INSTRUCTION-THROUGHPUT BOUND, not memory- or branch-bound:

  * IPC of 2.61 is high — the core is issuing near its width, not stalling.
  * Branch misprediction is 0.33% — essentially free. The bytecode dispatch
    loop predicts well (CPython here is built --with-computed-gotos).
  * L1 miss rate 2.46% and LLC miss rate 7.3% of references are unremarkable;
    the working set is small (a 67 KB input, 900 KB bzip2 block).

So the cost is simply the SHEER NUMBER of instructions retired: ~7.16 billion
to decompress 67 KB, about 106,000 instructions per input byte. That is
interpreter overhead, not algorithmic necessity — a C bzip2 decoder does this
in the low hundreds of instructions per byte.

Consequences:
  * Software optimisation should target INSTRUCTION COUNT (fewer Python-level
    operations per decoded symbol), not cache locality. This matches the
    py-spy profile: move_to_front (15.8% self) rebuilds a 256-entry list per
    symbol, and find_next_symbol linearly scans the Huffman table per symbol.
  * Hardware acceleration is well justified: a dedicated Huffman decoder +
    MTF unit would replace billions of interpreter instructions with a few
    cycles per symbol, and the small working set means it needs little
    memory bandwidth.
